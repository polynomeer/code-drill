# 해설

## 관찰

구간 `[i, j)` 의 합은 누적합의 차 `P[j] - P[i]` 다. 그래서 문제는 `i < j` 이고 `lower <= P[j] - P[i] <= upper` 인 쌍의 수를 세는 것이다. 원소가 `10^9` 이고 `10^5` 개라 누적합은 `Int` 를 넘는다 — `Long` 이어야 한다.

## 접근

역전 쌍 세기의 뼈대다. 누적합 배열을 절반으로 나눠 양쪽 안의 쌍은 재귀에 맡기고, 왼쪽의 `i` 와 오른쪽의 `j` 로 이루어진 쌍만 이 단계에서 센다. 양쪽이 각각 **정렬돼** 있으면 왼쪽의 `P[i]` 하나에 대해 `P[j] - P[i]` 가 범위에 드는 `j` 는 오른쪽에서 연속한 구간이고, `P[i]` 가 커질수록 그 구간의 양 끝은 오른쪽으로만 움직인다. 그래서 포인터 둘로 한 번에 센다. 세고 나서 양쪽을 병합해 정렬해 두면 위 단계가 같은 성질을 쓴다. `i < j` 라는 조건은 왼쪽·오른쪽으로 나눈 것이 저절로 지킨다 — 정렬해도 왼쪽 것은 여전히 왼쪽에서 왔다.

## 복잡도

O(n log n) 시간, O(n) 공간. 모든 쌍을 보면 O(n²) 이고 10 만에서 50 억이다.

## 발전 과정

구간을 전부 세는 풀이 → 누적합으로 쌍 세기(여전히 n²) → 정렬된 절반 위의 두 포인터. 셋째가 왜 맞는지 — 왜 `i < j` 가 지켜지고 왜 포인터가 되돌아가지 않는지 — 를 말할 수 있어야 한다.

## 흔히 무너지는 곳

누적합을 `Int` 로 두는 것, 경계를 미만으로 보는 것, 누적합의 0 번을 빼서 원소 하나짜리 구간을 놓치는 것.
