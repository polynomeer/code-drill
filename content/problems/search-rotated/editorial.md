# 해설

## 관찰

잘라 붙인 배열의 가운데를 보면, 잘린 자리는 왼쪽 반이나 오른쪽 반 중 한쪽에만 있다. 그래서 **적어도 한쪽은 정렬돼
있다** — `nums[lo] <= nums[mid]` 면 왼쪽이다. 정렬된 쪽은 양 끝 값으로 범위를 알 수 있으므로, 찾는 값이 그 범위에
있는지 바로 판단해 절반을 버린다.

## 접근

질문마다 이분 탐색한다. 왼쪽이 정렬돼 있고 `nums[lo] <= t < nums[mid]` 면 왼쪽으로, 아니면 오른쪽으로. 오른쪽이 정렬돼
있고 `nums[mid] < t <= nums[hi]` 면 오른쪽으로, 아니면 왼쪽으로. 원소가 하나 남아 `lo == mid` 면 왼쪽이 정렬된 것으로
봐야 하므로 비교는 `<=` 다. 못 찾으면 `-1`.

## 복잡도

질문마다 O(log n), 전체 O(q log n).

## 발전 과정

잘린 자리(가장 작은 값의 자리)를 먼저 이분 탐색으로 찾고, 찾는 값이 어느 쪽 정렬 구간에 드는지 골라 보통의 이분
탐색을 해도 같다. 값이 겹칠 수 있으면 `nums[lo] == nums[mid]` 에서 어느 쪽이 정렬됐는지 알 수 없어 최악 O(n) 이 된다.

## 흔히 무너지는 곳

- 왼쪽이 정렬됐는지를 `<` 로 본다.
- 회전을 무시하고 보통의 이분 탐색을 한다.
- 없는 값에 끝난 자리를 돌려준다.
- 질문마다 앞에서부터 훑는다.
