# 해설

## 관찰

두 번씩 나올 때는 전부 XOR 하면 짝이 사라진다. 세 번씩이면 XOR 은 소용없다 — `x ^ x ^ x = x`
라 세 번 나온 수가 그대로 남는다. 대신 비트 자리마다 보면, 세 번 나오는 수는 그 자리에 0 또는 3
을 보태고 한 번 나오는 수는 0 또는 1 을 보탠다.

## 접근

32 개 비트 자리 각각에 대해 1 인 원소의 수를 센다. `개수 % 3` 이 0 이 아니면 답의 그 비트는 1
이다. 부호 비트(31)까지 세고 `answer or (1 shl bit)` 로 합치면, 답이 음수일 때 부호 비트가
1 이 되어 `Int` 가 알아서 음수를 만든다.

## 복잡도

O(32n) 시간, 추가 공간 O(1). 해시맵으로 세면 O(n) 시간이지만 O(n) 공간이다.

## 발전 과정

두 상태 변수(`ones`, `twos`)로 자리별 개수를 3진 상태 기계로 유지하면 훑기 한 번이지만,
32 번 훑는 것과 같은 O(n) 이고 읽기는 더 어렵다.

## 흔히 무너지는 곳

- 비트 31 을 빼고 센다 — 답이 음수면 부호가 사라진다.
- 나머지를 2 로 취한다 — 세 번 나온 수의 비트가 남는다.
- `3 × 합 − 합` 요령을 `Int` 로 한다 — 넘친다.
