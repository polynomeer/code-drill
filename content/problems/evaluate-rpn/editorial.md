# 해설

## 관찰

후위 표기식은 괄호가 필요 없는 표기법이다 — 연산자가 나올 때 그 앞의 두 값이 피연산자다. 그러니 피연산자는 쌓아 두고, 연산자를 만나면 둘을 꺼내 계산해 다시 쌓으면 된다. 순서가 있는 연산(빼기·나누기)에서는 **나중에 꺼낸 것이 앞**이다.

## 접근

토큰을 훑는다. 0 이상이면 쌓고, 음수면 오른쪽·왼쪽 순으로 꺼내 연산하고 결과를 쌓는다. 나누기는 언어의 정수 나눗셈이 0 을 향해 자르는지 확인한다 — Kotlin 과 Java 는 그렇고, Python 의 `//` 는 내림이라 따로 맞춰야 한다.

## 복잡도

O(n) 시간, O(n) 공간.

## 발전 과정

이 문제는 알고리즘보다 **표기 규칙을 정확히 읽는 것**이다. 인코딩(음수는 연산자)은 입력에만 적용되고 중간 값에는 적용되지 않는다는 것, 나누기의 방향과 자르는 방식 — 셋 다 지문에 있다.

## 흔히 무너지는 곳

먼저 꺼낸 것을 앞 피연산자로 쓰는 것. 나눗셈을 내림으로 하는 것. 중간 값이 음수일 때 연산자로 착각하는 것.
