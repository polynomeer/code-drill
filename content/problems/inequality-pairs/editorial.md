# 해설

## 관찰

`d[i] = nums1[i] − nums2[i]` 로 두면 조건은 `d[i] ≤ d[j] + diff` (`i < j`) 다. 배열 하나에서 "앞의 값이 뒤의 값 + diff 이하"인
쌍을 세는 문제 — 뒤집힌 쌍 세기와 같은 모양이다.

## 접근

병합 정렬로 센다. 왼쪽 반과 오른쪽 반이 각각 정렬돼 있으면, 오른쪽의 `d[j]` 를 작은 것부터 보며 `d[j] + diff` 이하인 왼쪽
원소의 수를 포인터 하나로 센다 — `d[j]` 가 커지면 포인터는 앞으로만 간다. 센 뒤 두 반을 합친다. 재귀 없이 폭 1, 2, 4, … 의
이웃한 덩어리를 아래에서부터 처리하면 깊이 걱정이 없다.

쌍은 1 250 억까지 가므로 `Long` 으로 세고 마지막에 나머지를 취한다. 펜윅 트리(값을 좌표 압축해 앞선 값의 수를 센다)로도 같은
답이 나온다.

## 복잡도

O(n log n) 시간, O(n) 공간.

## 발전 과정

"조건을 한 배열의 i 몫과 j 몫으로 나눠 정렬 기반 세기로" 바꾸는 것은 뒤집힌 쌍, 중요한 뒤집힌 쌍(`a[i] > 2·a[j]`), 구간 합의
개수와 같은 계열이다.

## 흔히 무너지는 곳

- 등호를 빼고 센다.
- `diff` 를 앞쪽 값에 더한다.
- 쌍의 수를 `Int` 로 센다.
- 모든 쌍을 본다.
