# 해설

## 관찰

값이 `0`, `1`, `2` 셋뿐이다. 그러면 정렬은 "0 을 왼쪽 끝으로, 2 를 오른쪽 끝으로 보내는" 일이고, 1 은 저절로 가운데에 남는다. 이 제약을 읽지 않으면 O(n log n) 정렬을 쓰게 되는데 틀리지는 않아도 문제가 묻는 것은 아니다.

## 접근

포인터 셋 — `low`(0 의 경계), `mid`(지금 보는 칸), `high`(2 의 경계). `mid` 가 0 이면 `low` 와 바꾸고 둘 다 전진, 2 면 `high` 와 바꾸고 `high` 만 후퇴, 1 이면 `mid` 만 전진한다. 2 를 보낸 뒤 `mid` 를 옮기지 않는 이유는 오른쪽에서 온 값을 아직 보지 않았기 때문이다. `mid <= high` 인 동안 돈다.

두 번 훑는 방법도 있다 — 개수를 세고 0, 1, 2 를 차례로 쓴다. 한 번 훑기가 어렵다면 그것부터 한다.

## 복잡도

O(n) 시간, O(1) 추가 공간.

## 발전 과정

일반 정렬 → 개수 세어 두 번 훑기 → 포인터 셋으로 한 번 훑기. 마지막 것이 네덜란드 국기 문제다.

## 흔히 무너지는 곳

2 를 오른쪽으로 보낸 뒤 가운데 포인터도 옮기는 것. `mid < high` 로 멈춰 마지막 칸을 보지 않는 것.
