# 해설

## 관찰

`first` 의 앞 i 글자와 `second` 의 앞 j 글자의 답을 `L[i][j]` 라 하면, 마지막 글자가 같을 때 `L[i-1][j-1] + 1`, 다를 때 `max(L[i-1][j], L[i][j-1])` 이다. 표를 채우면 답은 오른쪽 아래 칸이다. 여기까지가 정확성이다.

이 문제가 어려운 자리는 그 다음이다. 두 문자열이 15,000 자면 표는 2 억 2 천만 칸이고 정수로 900MB — 메모리 한도의 세 배가 넘는다. 시간은 2 초 안에 든다. 그래서 표 전체를 든 풀이는 **느려서가 아니라 커서** 진다. 그런데 한 행을 채울 때 보는 것은 바로 앞 행과 같은 행의 왼쪽뿐이다.

## 접근

길이 `m + 1` 의 행 두 개만 둔다. `first` 의 글자마다 현재 행을 앞 행으로부터 채우고, 다 채우면 둘을 바꿔 끼운다. 답은 마지막 행의 마지막 칸이다.

## 복잡도

O(n · m) 시간, O(m) 공간. 시간은 줄일 수 없지만 공간은 표 하나에서 행 둘로 준다.

## 발전 과정

재귀 → 표 전체 → 행 둘. 두 번째에서 세 번째로 가는 것이 이 문제의 요점이며, 다른 2차원 DP 에도 그대로 옮겨지는 기술이다.

## 흔히 무너지는 곳

표 전체를 드는 것 — 메모리 초과다. 행을 바꿔 끼우지 않고 한 행에 덮어쓰는 것 — 대각선 값이 이미 갱신된 것을 읽는다. 글자가 맞았을 때 앞 행의 대각선이 아니라 같은 행의 왼쪽에 1 을 더하는 것 — 한 글자를 두 번 센다. 탐욕으로 다음 같은 글자를 짝짓는 것.
