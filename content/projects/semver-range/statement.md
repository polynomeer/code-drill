# 버전 범위 맞추기

패키지 관리자가 "`^1.2.3` 에 맞는 가장 높은 버전"을 고르는 부분을 만든다. `src/semver/Version.java` 와
`src/semver/Range.java` 를 완성한다.

## 버전 — `Version.parse(text)`

`MAJOR.MINOR.PATCH`, 그 뒤에 선택적으로 `-프리릴리스`, 그 뒤에 선택적으로 `+빌드`.

- 세 수는 음이 아닌 정수다. **앞자리 0 은 안 된다**(`01.2.3`). `int` 에 들어가야 한다.
- 프리릴리스와 빌드는 `.` 으로 나뉜 **식별자**들이다. 식별자는 비어 있지 않고 영문자·숫자·`-` 로만 된다.
  프리릴리스의 식별자가 숫자로만 되어 있으면 앞자리 0 이 안 된다(`1.0.0-01`). 빌드는 괜찮다.
- 앞뒤 공백, `v` 접두사, 그 밖의 모든 모양은 `IllegalArgumentException`. `null` 도 그렇다.

`major()`·`minor()`·`patch()`, `prerelease()`(식별자 목록, 없으면 빈 목록), `build()`(없으면 빈 문자열),
`isPrerelease()` 로 읽는다.

## 순서 — `compareTo`

1. 세 수를 앞에서부터 수로 비교한다.
2. 셋이 같으면 **프리릴리스가 없는 쪽이 크다** — `1.0.0-rc.1 < 1.0.0`.
3. 둘 다 프리릴리스면 식별자를 앞에서부터 비교한다. 둘 다 숫자로만 된 식별자면 **수로**, 아니면 글자의
   ASCII 순서로 비교한다. 숫자 식별자는 영문 식별자보다 작다. 앞이 모두 같으면 식별자가 적은 쪽이 작다.
4. **빌드는 순서에 쓰지 않는다.** 빌드만 다른 두 버전은 같은 버전이다 — `equals` 와 `hashCode` 도 그에 맞춘다.

`1.0.0-alpha < 1.0.0-alpha.1 < 1.0.0-alpha.beta < 1.0.0-beta < 1.0.0-beta.2 < 1.0.0-beta.11 < 1.0.0-rc.1 < 1.0.0`

## 범위 — `Range.parse(text)`

`||` 로 나뉜 **묶음** 중 하나라도 맞으면 맞는다. 한 묶음은 공백으로 나뉜 **비교식**이 모두 맞아야 맞는다.
앞뒤와 사이의 공백은 몇 칸이어도 된다.

| 비교식 | 뜻 |
|---|---|
| `1.2.3`, `=1.2.3` | 같다 |
| `>1.2.3` `>=1.2.3` `<1.2.3` `<=1.2.3` | 순서대로 |
| `~1.2.3` | `>=1.2.3 <1.3.0` |
| `^1.2.3` | `>=1.2.3 <2.0.0` — 0 이 아닌 가장 왼쪽 수까지는 고정한다: `^0.2.3` 은 `>=0.2.3 <0.3.0`, `^0.0.3` 은 `>=0.0.3 <0.0.4` |
| `*` | 무엇이든 |

연산자와 버전 사이에는 공백이 없다. 버전은 위의 완전한 모양만 받는다(`^1.2` 는 안 된다). 빈 묶음, 빈 범위,
그 밖의 모양은 `IllegalArgumentException`.

### 프리릴리스는 초대받아야 들어온다

프리릴리스 버전은 비교식을 모두 만족해도, **그 묶음 안에 세 수가 같은 프리릴리스 버전을 적은 비교식이
있을 때만** 맞는다. 누군가 `^1.2.3` 을 적었다고 `1.3.0-beta` 를 받고 싶어 한 것은 아니다.

- `^1.2.3` 은 `1.3.0-beta` 에 맞지 않는다. `*` 와 `>=1.0.0` 도 어떤 프리릴리스에도 맞지 않는다.
- `^1.2.3-beta.2` 는 `1.2.3-beta.4` 에 맞는다(`>=1.2.3-beta.2` 가 세 수가 같은 프리릴리스다). `1.2.4-beta.1`
  에는 맞지 않는다.
- 초대는 그 묶음 안에서만 통한다. 다른 묶음의 비교식은 소용없다.

## `satisfies(version)`, `maxSatisfying(versions)`

`maxSatisfying` 은 맞는 것 중 가장 큰 것, 없으면 `null`. 목록은 정렬되어 있지 않다. 같은 순서의 버전이
여럿이면 목록에서 먼저 나온 것.

## 제출

`src/semver/` 의 두 파일을 고친다. 시그니처는 그대로 두고 필드·생성자·도우미는 마음대로 더한다. `tests/`
아래의 파일은 채점 때 숨은 스위트로 덮인다. 테스트는 `import static codedrill.Assertions.*;` 의
`assertEquals`·`assertTrue`·`assertFalse`·`assertNull`·`assertThrows` 를 쓴다 — 표준 라이브러리 외의
의존성은 없다. 테스트는 이름이 `Test` 로 끝나는 클래스의 `public void test…()` 메서드다.
