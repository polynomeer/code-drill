# 해설 — 만료가 있는 LRU 캐시

두 규칙이 겹친다. **최근 사용 순서**와 **만료 시각**. 둘을 한 구조에 두려 하면 꼬인다 — 순서는
접근 순서 `LinkedHashMap` 이 맡기고, 만료는 항목에 시각 하나를 적어 두는 것으로 끝난다.
`accessOrder = true` 인 `LinkedHashMap` 은 `get` 이 항목을 뒤로 보내므로 앞이 가장 오래 쓰지
않은 것이다. 접근 순서가 아닌 기본 `LinkedHashMap` 을 쓰면 LRU 가 아니라 FIFO 가 된다 — 조회가
순서를 바꾸지 않아 "최근에 쓴 것을 내보내는" 캐시가 된다.

만료는 **읽는 쪽에서** 처리한다. 따로 도는 타이머는 시계가 주입되는 순간 의미가 없다. `get` 은
만료면 지우고 `null`, `size` 와 `keys` 는 먼저 만료된 것을 쓸어 낸다. 경계는 포함이다 —
`t >= 만료 시각` 이면 만료. `>` 로 두면 정확히 만료 시각에 조회한 값이 살아 있다.

용량은 **만료되지 않은 항목**의 것이다. 가득 찼을 때 먼저 만료된 것을 쓸어 내고, 그래도 가득
차 있을 때만 가장 오래 쓰지 않은 것을 내보낸다. 순서를 바꾸면 만료된 항목 때문에 멀쩡한 항목이
나간다. 이미 있는 키를 다시 넣는 것은 새 항목이 아니다 — 값·만료·순서만 새로워지고 아무것도
나가지 않는다.
