# UI 개편 계획

> **역할**: 웹 UI·디자인·기능을 어떤 순서로 상용 수준까지 고치는가
> **단일 출처**: UI 개편 단계의 순서, 화면별 목표 구조, 디자인 시스템과 프런트엔드 기반 채택 결정
> **갱신 트리거**: 한 단계를 닫았을 때, 디자인 `.docx` 가 개정됐을 때, 채택한 라이브러리를 바꿨을 때

왜 고쳐야 하는지 — 지금 화면이 어떻고 상용 플랫폼은 어떤지 — 는
[ux-benchmark.md](ux-benchmark.md) 에 있다. 이 문서는 **무엇을 어떤 순서로** 바꾸는가만 다룬다.

디자인 규칙의 원본은 [specs/](specs/) 의 두 디자인 문서다 — 디자인 설계서
(`code_drill_design_spec.docx`, 아래 **DS**)와 UI 디자인 문서(`code_drill_ui_design_document.docx`,
아래 **UI**). 토큰 값·문구·상태 표처럼 거기 이미 적힌 것은 옮겨 적지 않고 절 번호로 가리킨다.
이 문서에 새로 적는 것은 원본이 정하지 않았거나, 원본끼리 어긋나 **여기서 고른 것**뿐이다.

## 0. 한 줄 요약

기능은 거의 다 있다. 없는 것은 **화면**이다. 열일곱 개 패널이 한 페이지 두 열에 쌓여 있고,
지문과 에디터가 3,700px 떨어져 있다. 개편의 첫 일은 기능을 더하는 것이 아니라
**라우팅·앱 셸·Workspace 레이아웃**으로 이미 있는 기능에 자리를 주는 것이다.

## 1. 개편 원칙

| 원칙 | 이 개편에서의 뜻 |
|---|---|
| 기능 동등 먼저 | 단계마다 기존 패널을 **새 자리로 옮기고** 끝낸다. 옮기는 단계에서 기능을 빼지도 더하지도 않는다. 스모크와 `pnpm test` 가 개편 전후로 같아야 한다 |
| 화면 하나 = 일 하나 | 한 URL 은 한 가지 1차 행동을 갖는다 (UI §2.3 의 화면 ID). 패널은 그 행동을 돕는 자리에만 붙는다 |
| 토큰 없이 색 없다 | 컴포넌트 CSS 에 hex 를 직접 쓰지 않는다. 색·간격·반경·그림자·모션은 전부 토큰이다 |
| 원본 문구를 쓴다 | 판정·저장·분석 문구는 DS §17, UI §9.3 의 표를 그대로 쓴다. 새 문구가 필요하면 그 표에 맞춘다 |
| 번들 예산을 지킨다 | 첫 화면 gzip 한도는 `web/scripts/bundle-budget.mjs` 가 정한다. 새 의존성은 아래 §3 의 목록과 **직접 잰** 크기를 거친다 |

## 2. 원본끼리 어긋나는 것 — 여기서 고른 것

| 주제 | DS | UI | 고른 것 | 이유 |
|---|---|---|---|---|
| 테마 | §13.1 Light·Dark 두 벌 | §6.1 Light 한 벌 | **DS 를 따른다.** 기본값은 System, 에디터는 두 테마 모두 어둡게 (`editor.base`) | 지금 사용자는 어두운 화면에 익숙하고, 코딩 플랫폼 사용자의 다수가 다크를 쓴다. 한 벌만 지으면 다른 한 벌을 나중에 다시 검수해야 한다 |
| 본문 크기 | §13.2 Body 15/24 | §6.2 Body 14 | **14/22** (지문은 15/24) | 데이터 밀도가 높은 표·패널은 14, 길게 읽는 지문만 15 |
| 굵기 | §13.2 Bold·Semibold | §6.2 500 | **제목 600, 본문 400, 라벨 500** | Pretendard 의 500 은 한글 제목에서 위계가 약하다 |
| 반경 | §13.3 4/8/12 | §6.3 8~10 / 12~14 | **4 / 8 / 12** | 표·코드 블록이 많아 작은 반경이 정렬선을 덜 깬다 |
| 상단 바 | §6.1 56px | §4.1 50px | **전역 헤더 56, Workspace 툴바 44** | 둘은 다른 바다. Workspace 는 전역 헤더를 접고 툴바만 남긴다 |
| 화면 폭 | §15.1 다섯 구간 | §8.1 네 구간 | **DS §15.1** | 1440 이상 3열 구간이 있어야 Workspace 보조 패널 자리가 정해진다 |

## 3. 프런트엔드 기반 채택

U0 전의 `web/` 은 React + Monaco 만 썼고, 라우팅·서버 상태·마크다운·아이콘·컴포넌트가 전부
없었다. 아래를 들인다. 크기는 gzip 기준이고 **실제로 번들해서 잰 값**이다 — 문서에 적힌
크기를 믿었다가 한 번 틀렸다 (라우팅 줄). 첫 화면에 들어가는지를 함께 적는다.

| 필요 | 채택 | 크기 | 첫 화면 | 대안을 버린 이유 |
|---|---|---|---|---|
| 라우팅 | `wouter` | 3KB | 예 | 처음엔 `react-router` 를 들였는데 쓰는 것만 번들해도 **32KB** 였다 (이 표에 14KB 로 적혀 있었다). 데이터 로더는 react-query 가 맡으므로 경로 일치·링크·404 만 있으면 되고, 화면이 열 개 남짓이라 손으로 적는 라우트 표로 충분하다 |
| 서버 상태 | `@tanstack/react-query` | 10KB | 예 | 지금은 패널마다 `useEffect` + `refreshKey` 숫자로 다시 읽는다. 캐시·재시도·포커스 재검증·낙관적 갱신을 패널마다 다시 짓는 셈이다 |
| 지문 마크다운 | `marked` + `DOMPurify` | ~20KB | 아니오 (Workspace 청크) | `react-markdown` + remark 는 두 배 크다. 지문은 신뢰된 콘텐츠지만 질문 게시판 본문과 렌더러를 공유하므로 정화는 빼지 않는다 |
| 분할 패널 | `react-resizable-panels` | ~8KB | 아니오 | 키보드 조절과 `aria-valuenow` 를 기본 제공한다 (UI §8.2 의 요구 그대로) |
| 아이콘 | `lucide-react` (개별 import) | 아이콘당 <1KB | 예 | UI §7.2 의 아이콘 이름(`circle-check`, `timer-off`, `memory-stick`, `triangle-alert`)이 이미 Lucide 이름이다 |
| 글꼴 | Pretendard Variable (동적 subset), JetBrains Mono | `@font-face` CSS 17KB + 쓰인 글자의 조각만 | **아니오** — `main.tsx` 가 늦게 불러온다 | 시스템 글꼴은 OS 마다 한글 자형과 폭이 달라 표 정렬이 흔들린다. 동적 subset CSS 가 진입에 들어가면 그것만으로 첫 화면이 20KB 는다 |
| 대화상자·메뉴 | 브라우저 `<dialog>` 와 Popover API | 0 | — | `showModal()` 이 focus trap·Esc·배경 비활성을, `popover` 가 바깥 클릭·Esc 닫힘을 준다. 처음엔 Radix 를 계획했지만 남는 일이 "닫으면 연 요소로 포커스 복귀" 하나라 직접 쓴다. Tooltip·Combobox 처럼 브라우저가 주지 않는 것이 필요해지면 그때 Radix 를 다시 본다 |

들이지 않는 것: CSS-in-JS 런타임, 컴포넌트 키트 통째(MUI·Chakra), 차트 라이브러리 통째.
스타일은 **CSS Modules + 토큰 CSS 변수**로 간다 — 지금 `styles.css` 한 파일 1,300줄을
컴포넌트 옆으로 나눠 옮기는 데 가장 적은 변환이 든다. 차트는 필요한 두세 종(히트맵·레이팅
선·분포 막대)을 SVG 로 직접 그린다.

**전역 헤더** (DS §2.2): 로고 / 문제 / 훈련 / 역량 / 대회 / 검색(⌘K) / 알림 / 아바타 메뉴.
Workspace·리플레이에서는 헤더를 접고 컨텍스트 툴바(문제 제목·상태·언어·저장 상태)만 남긴다.
모바일은 상단 로고·검색 + 하단 탭 4개(문제·훈련·역량·나).

**공개 범위 바꾸기는 백엔드 일이다.** 지금 `/problems` API 가 비로그인에 401 을 준다.
DS §11.1 은 탐색과 공개 본문을 로그인 없이 허용한다 — 목록·본문·대회 목록 세 엔드포인트를
익명 읽기로 연다. 익명 응답에는 `solved` 같은 사용자 필드가 없어야 한다.

## 5. 디자인 시스템

### 5.1 토큰

`web/src/design/tokens.css` 한 파일이 단일 출처다. 값은 DS §13.1 (색), 위 §2 의 결정
(타이포·반경), DS §13.3 (간격·컨트롤 높이), UI §9.1 (모션)을 옮긴다. 이름은 DS 의 점 표기를
CSS 변수로 바꾼다 (`color.bg.canvas` → `--color-bg-canvas`).

DS 표에 없어서 더해야 하는 토큰:

| 토큰 | 용도 |
|---|---|
| `--color-border-default`, `--color-border-strong` | 패널 경계(장식)와 입력 경계(UI 경계 3:1) 분리. 지금 `--border` 하나가 둘 다 맡아 입력 경계 대비가 1.2:1 이다 |
| `--color-bg-elevated` | Popover·Dialog·Drawer 표면 |
| `--color-on-brand` | 브랜드 배경 위 글자. 지금 주 버튼 대비가 3.2:1 로 AA 미달 |
| `--color-difficulty-{1..5}` | 난이도 배지. 색만으로 구분하지 않으므로 글자 라벨이 함께 간다 |
| `--color-verdict-system` | System Error 전용 중립색 (DS §7.4) |
| `--z-{drawer,popover,dialog,toast}` | 레이어 순서 |

Dark 값은 DS §13.1 의 Dark 열을 쓰되, **출시 전에 대비를 자동 검사**한다 (UI §11.3 마지막
항목이 미결로 남긴 것). `web/scripts/` 에 토큰 쌍의 대비를 재는 스크립트를 두고 `pnpm build`
에 건다.

### 5.2 컴포넌트

`web/src/design/` 에 둔다. DS §14.1·§14.2 의 목록이 범위이고, 상태 열을 전부 구현해야 끝난다.

| 묶음 | 컴포넌트 | 지금 대신 쓰는 것 |
|---|---|---|
| 행동 | Button(primary·secondary·tertiary·danger·icon), IconButton, Link | `button`, `.linklike`, `.primary` 세 가지 |
| 입력 | TextField, SearchField, Select, Combobox, Checkbox, Switch, Textarea | 맨 `input` — 문제집 이름 칸은 스타일이 없어 흰 칸으로 보인다 |
| 표시 | Badge(difficulty·verdict·state·tag), Chip(filter), Avatar, Kbd, ProgressBar, Meter | `.chip`, `.level`, `✓` 문자 |
| 구조 | Pane, SplitPane, Tabs, Drawer(bottom·side), Dialog, Popover, Menu, Tooltip | `.panel` 하나 |
| 데이터 | Table(정렬·고정 헤더·밀도), List, EmptyState, Skeleton, ErrorState, Pagination | `ul` + "불러오는 중…" 문장 |
| 피드백 | Toast, Banner(system·sanction·offline), InlineAlert | `p.warn` |
| 판정 | VerdictBadge, JudgeProgress, TestCaseCard, OutputDiff, CompileLog | `VerdictPanel` 안에 인라인 |
| 리플레이 | TraceTimeline, StateCanvas, StateInspector, CodeTraceLink | `ReplayView` 안에 인라인 |

**Storybook 대신 `/design` 라우트**를 개발 빌드에만 둔다. 컴포넌트마다 모든 상태를 한
화면에 늘어놓고, 그 화면을 Playwright 스크린샷 회귀의 기준으로 삼는다 (§8).

## 6. 화면별 목표

### 6.1 P-01 문제 탐색 `/problems`

UI §3 이 기준이다. 지금과 다른 점만 적는다.

- **표로 바꾼다.** 열: 상태 아이콘 · 번호 · 제목(태그는 2차 줄) · 난이도 배지 · 정답률 ·
  학습 기록(리플레이·오답 분기 수) · 예상 시간. 행 전체가 링크다 (`<a>` — 새 탭으로 열 수 있어야 한다).
- **문제 번호를 준다.** slug 는 URL 용이고 사람이 부르는 이름이 아니다. 공개 순서대로
  1000번부터 고정 번호를 매기고 바꾸지 않는다 (백엔드 + 카탈로그).
- **정렬**: 번호·난이도·정답률·푼 사람 수. URL 쿼리에 산다.
- **태그는 접는다.** 지금 태그 칩 35개가 목록보다 먼저 400px 를 차지한다. 상위 8개 +
  "더 보기" 팝오버, 태그 검색.
- **페이지네이션**: 50행 페이지 + 하단 페이지 이동. 무한 스크롤은 "몇 번째 줄에 있었나"를 잃는다.
- **"아무 문제나"**: 지금 필터 안에서 안 푼 문제 하나로 바로 간다.
- **보조 열** (≥1280): 오늘의 처방 카드, 이번 주 목표 진행, 진행 중 대회 하나. 지금 왼쪽 열
  맨 위에 있는 대회 50개 목록은 `/contests` 로 옮긴다.
- 로딩은 행 모양 스켈레톤, 빈 결과는 적용된 필터와 "필터 초기화", 오류는 재시도.

### 6.2 S-01 풀이 Workspace `/problems/:slug/solve`

UI §4, DS §6 이 기준이다. **이 단계가 개편의 핵심이다.**

```
┌ 툴바 44px ─ ← 문제목록 │ #1042 구간 더하기 뒤의 배열 ✓ │ Kotlin ▾ │ 저장됨 │ ⚙ │ [실행] [제출] ┐
├──────── 문제 pane 38% ────────┬──────────── 에디터 pane 62% ─────────────┤
│ [문제][해설🔒][풀이][질문][제출] │ Monaco                                    │
│  지문(마크다운) · 예제 표 · 제약    │                                          │
│  ─ 풀기 전에 (접힘)                │                                          │
│                                  ├──────── 결과 drawer 0/32/55% ───────────┤
│                                  │ [테스트케이스][실행 결과][판정][리플레이]   │
└──────────────────────────────────┴──────────────────────────────────────────┘
```

| 지금 패널 | 새 자리 |
|---|---|
| 문제 본문 (`pre` 로 원문 마크다운 노출) | 문제 pane "문제" 탭, 마크다운 렌더 + 예제 입출력 표 + 제한 블록 |
| 테스트 그룹 가중치 | 문제 pane 하단 "채점 기준" 접이식 |

- 단축키 (DS §6.4): 실행 ⌘↵, 제출 ⌘⇧↵, drawer ⌘J, 문제/에디터 포커스 ⌥1/⌥2, 명령 팔레트 ⌘K,
  문제 pane 접기 ⌘\\. 툴바 버튼 툴팁에 단축키를 함께 적는다.
- 에디터 설정 (DS §11.2 Editor): 글꼴 크기, tab size, keymap(기본·Vim·Emacs — `monaco-vim`
  은 설정을 켤 때만 불러온다), 미니맵, 줄바꿈. 서버의 사용자 설정에 저장한다.

- 판정이 끝나면 drawer 를 자동으로 펼치고 판정 탭으로 간다 (UI §8.3).
- pane 비율·drawer 높이·열린 탭은 기기별 로컬 저장 (UI §8.3 "사용자+기기").
- 768~1279: 문제 pane 기본 접힘. <768: 문제/코드/결과 세 탭 전환, 코딩은 "데스크톱 권장" 안내.

### 6.3 판정 결과와 제출

DS §7, §9 가 기준이다.

- **JudgeProgress**: 다섯 단계를 가로 스텝으로. 지금은 `채점 중 — RUNNING` 처럼 enum 이 그대로
  보인다. 문구는 DS §7.1 표.
- **VerdictBadge**: 아이콘 + 문구 + 의미색 (UI §7.2). 맞았습니다는 시간·메모리·통과 그룹을
  큰 숫자로, 틀렸습니다는 **첫 실패 케이스의 입력·기댓값·실행값 diff 가 1차 정보**다 (UI §4.2).
- **OutputDiff**: 줄/글자 모드, 공백 표시 토글, 긴 출력은 첫 차이 주변만 (UI §7.3 Diff Block).
- **System Error** 는 다른 모양으로 — 코드 고치기 CTA 대신 "다시 시도"와 신고 ID (DS §7.4).
- **정답 이후 카드** (DS §10.3): 리플레이 보기 · 해설 · 다른 풀이 · 후속 문제 · 복습 예약.
  지금 맞힌 뒤 화면에는 공유·기부 버튼만 있고, 다음에 무엇을 할지 묻지 않는다.
- **`/submissions`**: 판정·언어·문제·기간 필터, 상대 시간, 리플레이 상태 열 (DS §9.1).
- **코드 비교**: 같은 문제 내 제출 두 개, Monaco diff editor (side-by-side, 좁으면 inline).
  지금 `CodeView` 는 바로 이전 제출과의 diff 만 본다.

### 6.4 R-01 리플레이 `/submissions/:id/replay`

UI §5, DS §8 이 기준이다. 지금 `ReplayView` 는 Workspace 오른쪽 열의 패널 하나라 UI §5.1 의
네 영역(Code 30 / Canvas 48 / Inspector 22 / Timeline)이 들어갈 폭이 없다. 전용 라우트로
빼서 전체 화면을 준다.

- 타임라인: 일반·중요·오류 세 크기 마커, 스크럽, 0.5/1/2x, Shift+←/→ 로 중요 이벤트 점프 (UI §5.3).
- Code Pane 의 활성 줄과 Canvas 선택이 양방향으로 이어진다 (`CodeTraceLink`). 지금은 코드 pane 이 없다.
- 최초 분기점 카드는 UI §5.4 의 다섯 단계 구조로.
- `prefers-reduced-motion` 에서 애니메이션을 즉시 전환으로 (UI §5.3).
- 모바일: Canvas 중심 + Inspector bottom sheet.

### 6.5 훈련·역량 `/training`, `/competencies`

- `/training`: 오늘의 처방(지금 `TodayPanel`) 카드 1~2개를 크게, "시작·교체·미루기" 세 행동
  (UI §9.4). 아래에 진행 중인 코칭 세션과 전이 과제.
- `/competencies`: 지금 19줄 목록 중 대부분이 "아직 재지 않음 · 근거 없음" 이다. 재지 않은 역량은
  한 줄로 접고("12개 역량은 아직 근거가 없습니다 — 진단 시작"), 잰 것만 Level·Confidence 를
  분리한 막대로 그린다. 역량군 다섯은 요약 카드, 노드를 누르면 오른쪽 Evidence drawer.
- 주간 리포트는 `/competencies` 의 탭 하나.

### 6.6 대회 `/contests`

- 로비: **진행 중 / 예정 / 끝남** 세 구획, 끝난 것은 페이지네이션. 지금은 끝난 대회 50개가
  한 목록에 시간순 구분 없이 나온다.
- 대회 화면: 남은 시간 카운트다운(헤더 고정), 문제 목록 + 내 상태, 순위표(고정 헤더, 내 행 강조).
- 프로필에 레이팅 선 그래프와 대회 이력.

### 6.7 프로필 `/u/:handle` — 새로 짓는다

상용 플랫폼 전부가 가진 화면인데 지금 없다 ([ux-benchmark.md](ux-benchmark.md) §3).
푼 문제 수(난이도별), 활동 히트맵(1년), 연속 일수, 레이팅, 공개한 풀이, 기여 등급.
**역량 Level 은 본인에게만** 보인다 — 공개 프로필에 내걸면 No false precision 과 어긋나는
비교가 시작된다.

### 6.8 운영 콘솔 `/admin` — 새로 짓는다

지금 검수·재채점 승인·제재·유사도 신호·기부 검수가 **API 로만** 있다. 운영자는 curl 로 일한다.
역할별로 보이는 큐 화면을 짓는다: 문제 버전 검수(검증 보고서 digest), 재채점 요청·2인 승인,
신고·제재·이의, 유사도 신호 쌍(두 소스 나란히), 아레나 기부 검수. 감사 로그 열람.
일반 사용자 번들에 섞이지 않게 별도 청크로 나눈다.

### 6.9 인증과 첫 경험

- 로그인 화면에 소셜 로그인(GitHub·Google) 자리, 비밀번호 재설정 경로.
- 비로그인 Workspace: 로컬 초안으로 시작하고, 제출 때 로그인 → 초안 병합을 묻는다 (DS §11.1).
- 가입 직후 3문항 온보딩(목표·주 언어·현재 수준) → 진단용 문제 세트로 처방의 첫 근거를 만든다.
  지금은 가입 직후 처방이 "근거 없음"으로만 채워진다.

## 7. 콘텐츠 표현

UI 를 바꾸면 드러나는 콘텐츠 쪽 일이다. 저작 규칙은 `content/tools/README.md` 가 단일 출처이므로
규칙을 정하면 그쪽을 고친다.

- **지문에서 리플레이 계측 안내를 뺀다.** 190개 지문 전부가 `## 실행 리플레이 계측 (선택)` 절을
  싣는다. 문제가 아니라 플랫폼 기능의 설명이다 — Workspace 의 리플레이 탭 도움말로 한 번만 둔다.
- **지문이 풀이 기법을 말하지 않게 한다.** 기법 이름이 지문에 직접 적힌 것이 7개다
  (예: `apply-range-updates` 의 "차분 배열"). 힌트는 `hints.yaml` 의 몫이다. `validateContent` 에
  금칙어 검사를 더한다.
- 예제는 지문 본문의 코드 블록이 아니라 manifest 의 `samples` 로 표에 그린다.
- 난이도 표기: UI §3.4 는 "Silver 3, Gold 5" 같은 세분 등급을 권한다. 지금 5단계
  (입문~최상)는 유지하되 배지 모양을 등급형으로 바꾸고, 세분 등급은 표본이 충분해진 뒤
  정답률 기반으로 매긴다 (No false precision).

에디터가 한 화면에 없다)이 여기다. 탐색은 지금도 동작은 한다.

### U0 에서 한 것과 남긴 것

- 토큰은 `web/src/design/tokens.css` 하나다. 옛 `styles.css` 의 변수 여덟 개는 그 토큰의 별칭이
  됐고, hex 가 하나도 남지 않았다 — 옛 화면도 라이트·다크를 따라간다. 별칭은 화면이 `design/`
  으로 옮겨 갈 때마다 줄어든다.
- 테마는 `<html data-theme>` 한 곳이 정하고, 첫 페인트 전 인라인 스크립트(`index.html`)가 채운다.
  선택은 기기별 localStorage 다. 서버 설정으로 옮기는 것은 설정 화면(U8 이후)과 함께.
- 계정 설정은 왼쪽 열 패널에서 **대화상자**로 옮겼다. 라우트(`/settings`)로 빼면 지금 화면은
  고른 문제를 주소에 두지 않아서, 설정에 다녀오면 풀던 문제를 잃는다. U1 이 문제를 주소에 올린
  뒤에 라우트로 뺀다.
- 서버 상태 캐시는 문제 목록 하나에만 걸었다 — 오류 상태와 "다시 시도"가 생겼다. 나머지 패널은
  자기 화면이 옮겨 갈 때 함께 바꾼다.
- `pnpm build` 앞에 토큰 대비 검사(`scripts/contrast.mjs`)가 붙었다. 두 테마의 글자·경계 쌍을 잰다.
- 브라우저 검사(`pnpm e2e`)는 백엔드 없이 도는 화면만 본다 — `/design` 과 로그인. 판정 흐름 E2E 는
  앱 셋을 띄워야 해서 U1 에 붙인다. 시각 회귀 스크린샷도 U1 부터다 — 지금 찍으면 곧 바뀔 화면의
  기준만 쌓인다.
- 첫 화면 번들은 94KB → 117KB (react-query 10, 디자인 시스템·아이콘 7, wouter 3). 한도를 140KB 로
  올렸다. 근거는 `web/scripts/bundle-budget.mjs` 에 있다.
- 열어 보다가 함께 고친 것: 375px 에서 문서 폭이 804px 로 넘치던 것 — 1열 그리드가 가장 긴 줄만큼
  늘어나고 있었다.
