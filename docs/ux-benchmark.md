# UI 현황 진단과 상용 플랫폼 벤치마크

> **역할**: 지금 웹 UI 는 상용 코딩 플랫폼과 견줘 어디가 모자라고, 그 근거는 무엇인가
> **단일 출처**: 웹 UI 현황 진단 결과와 상용 플랫폼 비교
> **갱신 트리거**: [ui-overhaul.md](ui-overhaul.md) 의 한 단계를 닫아 §1 의 진단이 낡았을 때, 비교 대상 플랫폼이 핵심 화면을 크게 바꿨을 때

무엇을 어떤 순서로 고칠지는 [ui-overhaul.md](ui-overhaul.md) 가 정한다. 이 문서는 **왜**만 다룬다.
조사 시점은 `git log -1 -- docs/ux-benchmark.md` 가 답한다. 상용 플랫폼은 자주 바뀌므로
§2 를 인용하기 전에 해당 사이트를 다시 확인한다.

## 0. 결론

**판정·리플레이·역량 진단은 상용 플랫폼 어디에도 없는 수준까지 서 있다. 그것을 담는 화면은
상용 플랫폼 어디보다 뒤처져 있다.**

- 백엔드가 보장하는 것(격리, 판정 5종, 부분 점수, 재채점, 리플레이, 분기 진단, 변이 평가)은
  LeetCode·백준·프로그래머스보다 깊다. 오답의 **이유**를 실행 증거로 보여 주는 곳은 비교한 열한 곳
  중 하나도 없다 (§3.3).
- 그런데 웹은 **라우트 없는 한 페이지에 패널 열일곱 개를 두 열로 쌓은** 개발 콘솔 모양이다.
  상용 플랫폼이 모두 가진 분할 Workspace, 문제 번호, 프로필, 단축키, 렌더링된 지문이 없다.
  지금 화면으로는 백엔드의 깊이가 사용자에게 전달되지 않는다.
- 원본 디자인 문서(UI·DS)는 이미 상용 수준의 화면을 정의해 두었다. **설계가 모자란 것이 아니라
  설계를 아직 구현하지 않았다.** 개편의 대부분은 새 결정이 아니라 원본을 따라잡는 일이다.

## 1. 현황 진단

로컬 스택(`scripts/up.py`)에 붙여 1440×900 과 375×812 에서 직접 열어 보고, `web/src` 를 읽어
확인한 사실이다. 숫자는 측정값이다.

**U0 이후 닫힌 것** ([ui-overhaul.md](ui-overhaul.md) §9): 토큰·라이트/다크 테마(§1.3 첫 줄),
Pretendard·JetBrains Mono, 공용 컴포넌트, 흰 입력칸, 주 버튼 대비(이제 7.0:1), 입력 경계 대비,
`:focus-visible`, `prefers-color-scheme`·`prefers-reduced-motion`, 375px 가로 넘침.

**U1 이후 닫힌 것**: §1.2 의 풀이 화면 — 지문과 에디터가 한 화면에 나란하고, 지문이 마크다운으로
그려지고, 예제 표·단축키·에디터 설정·결과 창이 생겼다. 라우트가 섰다 (`/problems/:slug/solve`).

**U2 이후 닫힌 것**: 문제 번호, 표·정렬·쪽, 접힌 태그, 비로그인 탐색과 공개 읽기 화면, 끝난 대회
50개가 문제 목록을 밀어내던 것(목록이 자기 화면으로 나갔다). 처음 진단에는 "문제 목록 API 도
401" 이라고 적었는데 같은 포트를 쓰던 다른 앱의 응답이었다 — §1.1 의 그 줄은 고쳐 두었다.

**U3 이후 닫힌 것**: §1.2 의 enum 이 보이던 진행 표시, 공유·기부뿐이던 정답 이후 화면. §3.3 의 "무엇이
틀렸나"에 실행값이 더해졌다 — 상용 플랫폼처럼 실패한 예제의 입력·기댓값·실행값을 보인다. §3.1 의 "두 제출
비교"는 이제 아무 두 제출이다.

**U4 이후 닫힌 것**: §1.2 의 "리플레이가 Workspace 오른쪽 열 패널 하나다" — 리플레이는 이제 코드·상태·검사기·
타임라인을 갖춘 제 화면이다.

아래 표는 측정 당시 그대로 둔다 — 무엇이 왜 바뀌었는지의 기준이다.

### 1.6 잘 되어 있는 것

개편이 지켜야 할 것들이다.

- 필터 상태가 URL 에 산다. 검색은 250ms debounce (UI §3.3 그대로).
- 저장 충돌을 토스트가 아니라 배너로 남기고 서버·내 것 중 고르게 한다.
- 정답률을 표본이 적으면 그리지 않는다 (No false precision).
- Monaco 를 별도 청크로 미루고 첫 화면 번들 예산을 빌드가 검사한다.
- 리플레이 리듀서 불변식 테스트, 텍스트 폴백, ←/→/Home/End 키보드 조작.
- 판정과 상태를 색만이 아니라 글자로도 전한다.

## 2. 비교 대상

선정 기준: 국내 사용자가 실제로 쓰는 곳(백준+solved.ac, 프로그래머스), 세계 기준점(LeetCode,
Codeforces, AtCoder, HackerRank), 학습·코칭 경험이 강한 곳(Codewars, Exercism, NeetCode,
AlgoExpert, CodeSignal Learn, Boot.dev).

| 플랫폼 | 한 줄 | CodeDrill 이 볼 지점 |
|---|---|---|
| LeetCode | 인터뷰 준비의 기준점. 드래그·도킹 가능한 탭형 Workspace | Workspace 레이아웃, 결과 화면, 프로필, 학습 플랜 |
| Codeforces | 대회의 기준점. 낡은 UI, 브라우저 실행 없음 | 실시간 판정 진행, 해킹, 레이팅 색 띠, 가상 참가 |
| 백준 + solved.ac | 국내 문제 풀이의 기준점. 실패 케이스를 보여주지 않음 | 문제 번호 문화, 티어·클래스, 잔디, 기여 기반 난이도 |
| 프로그래머스 | 국내 코딩테스트 준비. 3분할 Workspace | 실행/제출 구분, 케이스 추가, 맞힌 뒤 다른 풀이 |
| AtCoder | 공식 해설이 강함. 전역 태그 탐색 없음 | 문제마다 공식 해설, 대회 중 AI 규칙 |
| HackerRank | 채용 B2B 중심 | 설정(vim·테마), AI 면접관 |
| Codewars | 단계(kyu) + 맞힌 뒤 풀이 투표 | "Best Practices / Clever" 투표, 스포일러 표시 |
| Exercism | 학습 모드·연습 모드, 사람 멘토링 | 잠금 해제형 경로, 관용구 피드백 |
| NeetCode | 의존 그래프 로드맵 | 진도를 공간으로 보여주는 로드맵 |
| AlgoExpert | 문제마다 단계별 힌트 2~4개 + 영상 | 점진 힌트, 보이는 테스트와 diff |
| CodeSignal Learn · Boot.dev | AI 튜터(Cosmo, Boots)가 답 대신 질문 | 소크라테스식 코칭, 사용량 제한형 AI |

| 대회 로비·카운트다운·순위표 | ● | ● | ◐ | ● | ◐ 목록뿐 |
| 다크·라이트 | ● | ○ / ● | ● | ○ | ◐ 다크만 |

| 비로그인 탐색 | ● | ● | ● | ● | **○** |

**CodeDrill 이 기본기에서 빠진 것은 전부 화면 쪽이다.** 백엔드 기능 칸(실행·제출 구분, 커스텀
케이스, 실패 케이스, 해설, 다른 풀이)은 이미 상용 평균 이상이다.

### 3.2 Workspace 레이아웃

| 항목 | LeetCode | 프로그래머스 | AlgoExpert | 원본(UI §4) | CodeDrill |
|---|---|---|---|---|---|
| 기본 분할 | 좌 지문 / 우 에디터 + 하단 결과 | 좌 지문 / 우상 에디터 / 우하 결과 | 좌 지문 / 우 에디터 + 하단 테스트 | 38 / 62 + drawer 32% | 두 열 스택 |
| 지문 쪽 탭 | 설명·해설·풀이·제출 | 없음 (별도 페이지) | 설명·힌트·영상 | (DS §7.3 drawer 탭) | 없음 |
| 크기 조절 | 드래그·도킹·탭 이동 | 드래그 | 드래그 | 핸들, 키보드 조절, 비율 저장 | 없음 |
| 결과 위치 | 하단 패널 | 하단 패널 | 하단 패널 | 하단 drawer, 판정 완료 시 자동 확장 | 에디터 아래 스택 |

세 곳이 모두 같은 골격(좌 지문, 우 에디터, 우하 결과)으로 수렴했고, 원본도 같은 골격을 정했다.
이 골격은 실험할 대상이 아니라 **사용자가 기대하는 문법**이다.

### 3.3 판정 결과 — CodeDrill 이 앞서는 곳

| 질문 | LeetCode | 백준 | Codeforces | CodeDrill |
|---|---|---|---|---|
| 무엇이 틀렸나 | 실패 입력·기댓값·출력 하나 | 판정만 | 대회 뒤 테스트별 | 공개 그룹의 케이스별 |
| 왜 틀렸나 | AI 채팅에 물어보기 | 블로그 | 블로그 | **최초 분기점 — 기준 풀이와 갈라진 걸음** |
| 실패 입력을 줄여 주나 | ○ | ○ | ○ | **● 반례 축소** |
| 실행 과정을 보나 | ◐ 디버거 (유료) | ○ | ○ | **● 의미 이벤트 리플레이 + 예측** |
| 내 테스트가 충분한가 | ○ | ○ | ◐ 해킹 | **● 변이 점검** |
| 성능은 남과 견줘 어떤가 | ● "Beats X%" 분포 | ○ | ○ | ○ — 의도적 (§4.3) |

**어느 플랫폼도 "판정 + 실패 케이스 하나" 이상을 설명하지 않는다.** CodeDrill 의 리플레이·분기
진단·반례 축소·변이 점검이 바로 그 빈자리를 채운다. 문제는 이 기능들이 지금 오른쪽 열 아래쪽
패널 안에 들어 있어, 오답을 받은 사용자가 거기까지 스크롤해야 발견한다는 것이다.

### 3.4 학습과 진도

| 패턴 | 어디서 | 쓸 만한 이유 | CodeDrill 의 대응물 |
|---|---|---|---|
| 티어 + 클래스(필수 문제 묶음, +/++ 장식) | solved.ac | 다음 목표가 늘 하나 보인다 | 처방이 같은 역할. 장식·진행률이 없다 |
| 태그별 레이팅 / Skills 버킷 | solved.ac, LeetCode | 역량 지도와 가장 가까운 기존 표현 | 역량 지도 — **실행 증거 기반**이라 더 정확하다. 표현이 목록이라 약하다 |
| 의존 그래프 로드맵 | NeetCode | 진도를 공간으로 본다 | DS §10.5 의 Competency graph 가 같은 것을 정했다. 아직 없음 |
| 학습 모드 / 연습 모드 | Exercism | 초보와 숙련자의 길을 가른다 | 원본의 자유·코칭·집중·평가 모드 (UI §9.6) |
| 오늘의 문제 + 연속 일수 | LeetCode, solved.ac | 재방문의 가장 강한 장치 | 처방은 있다. 연속 일수·히트맵 없음 |
| 기여자 투표로 매기는 난이도 | solved.ac | 저자가 아니라 푼 사람이 매긴다 | 정답률 기반 산출이 가능 — 표본이 쌓이면 |

### 3.5 코칭과 AI

## 4. 따라 할 것과 피할 것

### 4.1 그대로 따라 한다

- **좌 지문 / 우 에디터 / 하단 결과** 분할과 지문 쪽 탭(설명·해설·풀이·질문·제출).
- **실행 ⌘↵ / 제출 ⌘⇧↵** — 단축키 조합은 플랫폼마다 조금씩 다르므로 툴팁과 설정 화면에서 보여준다.
- **문제 번호.** 백준 사용자에게 문제는 번호로 불린다.
- **잔디(히트맵)·연속 일수·난이도별 푼 수** 프로필.
- **맞힌 뒤에 여는 다른 풀이와 투표** (프로그래머스, Codewars).
- **실시간 판정 진행 표시** — "test 7 실행 중"(Codeforces)·퍼센트(백준)처럼 지금 어디까지 왔는지.
- **대회 로비의 세 구획과 카운트다운, 레이팅 색 띠.**

### 4.2 고쳐서 따라 한다

- **티어·클래스 → 역량 기반 목표.** 푼 수가 아니라 역량 Level 이 오르는 묶음을 "다음 목표"로.
- **태그별 레이팅 → 증거 기반 역량 지도.** 레이더 차트 하나로 단정하지 않고 Level·Confidence 를
  분리한다 (DS §10.5).
- **AI 채팅 → 근거에 묶인 코칭.** 답을 말하는 대신 리플레이의 걸음·반례·코드 줄을 가리킨다
  (Evidence over answers).

### 4.3 피한다

- **"Beats X%" 성능 백분위.** 같은 코드를 다시 내도 값이 흔들려 사용자가 재제출로 숫자를 맞춘다.
  CodeDrill 은 성능을 그룹 판정(시간 제한 대비)으로 이미 말하고 있고, 분포를 보여주려면 측정 분산을
  함께 밝혀야 한다 (No false precision). 넣더라도 분산과 표본 수를 같이 그린다.
- **해설·핵심 기능의 유료 잠금** (LeetCode 에 대한 가장 흔한 불만). 과금은 코칭 사용량·고급 분석
  쪽에 둔다 — 원본 기획서의 수익화 단계에서 정할 일이다.
- **실패 케이스를 끝까지 숨기기** (백준·프로그래머스). CodeDrill 은 이미 공개 그룹을 보여준다.
  숨은 그룹도 최초 분기점의 **설명**은 줄 수 있다 — 입력을 드러내지 않고 무엇이 갈라졌는지만.
- **풀이 게시판의 저품질 범람.** 맞힌 사람만 쓰고, "도움됐다"가 정렬 기준인 지금 구조를 지킨다.

## 5. CodeDrill 만의 자리

비교한 열한 곳 모두 "몇 문제를 풀었나"와 "판정이 무엇인가"까지만 말한다. 왜 틀렸는지, 어떤 역량이
비었는지, 그 역량이 다른 문제로 옮겨 갔는지를 **실행 증거로** 말하는 곳은 없다.

그 자리를 사용자가 알아보려면 화면이 세 가지를 해야 한다.

1. **오답 직후 한 번의 클릭으로 최초 분기점에 닿는다.** 지금은 스크롤 두 화면 아래다.
2. **역량 지도가 프로필·처방·문제 목록 어디서든 보인다.** 지금은 Workspace 오른쪽 열 중간이다.
3. **기본기에서 감점당하지 않는다.** 분할 Workspace·단축키·렌더링된 지문·번호·프로필이 없으면
   사용자는 차별점에 닿기 전에 떠난다.

세 번째가 첫 번째 일이다. [ui-overhaul.md](ui-overhaul.md) 의 단계 순서가 이 판단을 따른다.
