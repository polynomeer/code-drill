## 문서 포맷

`docs/` 아래 모든 문서는 제목 다음에 세 줄 헤더를 둔다.

```markdown
# <제목>

> **역할**: 이 문서가 답하는 질문 한 줄
> **단일 출처**: 이 문서가 권위를 갖는 범위
> **갱신 트리거**: 무엇이 바뀌면 이 문서를 고쳐야 하는가
```

헤더는 문서를 살아있게 유지하는 장치다. **갱신 트리거를 못 쓰겠으면 그 문서는
독립 문서일 이유가 없다** — 기존 문서의 한 섹션으로 넣는다.

## 문서 작성 규칙

- **한 규칙은 한 문서에만.** 같은 규칙을 두 곳에 쓰지 않고 링크한다. 규칙을 바꿀 때
  고칠 파일이 하나여야 한다.
- **환경이 아는 사실은 적지 않는다.** 디렉터리 트리, 스크립트 목록, 의존성 버전은
  `ls`·설정 파일·`--help`가 답한다. 문서에는 조회로 알 수 없는 것 — 이유, 관례,
  함정 — 을 적는다.
- **날짜·작성자·버전을 본문에 적지 않는다.** `git log -1 -- <파일>`이 답한다.
  본문에 적으면 반드시 낡는다.
- **금지보다 목표를 쓴다.** "X 하지 마라"보다 "Y 하라"가 에이전트에게 더 잘 작동한다.
- **분량을 줄인다.** 읽어도 행동이 바뀌지 않는 문장은 지운다.

## 보관 정책

규칙이 통째로 대체되면 지우지 않고 `archive/<YYYY-MM-DD>-<이름>/`으로 옮긴다.
`git mv`로 옮겨 이력을 유지한다. 보관된 문서는 현재 규칙이 아니므로 링크로
참조하지 않는다 — 왜 바뀌었는지 추적할 때만 연다.
